When I started building this blog I was curious how long I'd keep it going and what I'd write about. Indeed, here's a slightly lairy/embarrassing passage from the second post 11 years ago:

...I've already built an mvp of the blog - look it’s glowing at you from your screen. You're reading it now. It is a side project squeezed into the small gaps that life sometimes provided but it does give an idea of the thoughts and process that I put into building a project. There were some interesting decisions along the way, I discovered some new tools and had problems to overcome. I’m still iterating and improving. I reckon there are enough navel gazing, meta posts in this project to pollinate the blog and hope it is flourishes into something beautiful.

- Mike Harris, Building a blog, Mar 2015

Meta navel gazing

So that was quite prescient - I have built lots of little things into the blog - from RSS feeds through to extravagant animations, progressive web apps through to automated lighthouse reports. Learnt a bunch along the way and each fun feature provided content for various posts. What I have failed to do is to keep all the libraries and dependencies up to date. All the less fun that is hard to motivate yourself to do for one of many side projects.

Upgrading the blog

I have tried to upgrade things but this is a fun project and I know how to manage dependencies so the energy to push through and do the dirty work just wasn't there. I remember trying to upgrade handlebars (a templating engine) a few times and getting a bit stuck. If I really wanted to I'd have sorted it out but it never was that important to a side project. Almost anything in life was more important! Fortunately AI came along and in the space of an afternoon my pal Claude worked alongside me in the background and we sorted out all the dependencies. We also did a bunch of slightly tedious but essential things such as expanding the test suite, providing better tooling along the way plus adding in workflows and types. It's a real project now!

Smoothness of AI just gets you going

My friend Werner wrote a longer, more detailed post about using AI to tackle often tedious tasks. Tasks which in the past would have sucked up a lot of time and been intimidating to start but now you're much more likely to tackle.

AI for the tech, me for the words

AI can fix the tech but I'll be writing the words. It goes through AI to check spelling and flag where it thinks grammar might be off but I usually roll with what I think and just use this to tidy up obvious errors.

Conclusion

The building part of the blog has done its job - I've learnt loads along the way, written posts and done talks on how I built it. I'll probably do some fun features in the future but it's a bit of a relief to have finally got the project into a decent state. Almost every job I've interviewed for I've shared a link to a blog post - I'd now feel happier if they actually looked at the code it was running on.

Appendix - Modernising the stack

A list of everything that my pal Claude built to bring this project up to date

  • Modernise the stack and add CI — dragged the blog off a 2018-era dependency set and replaced the CI stub with a workflow that actually checks the app boots.
  • Add prettier — config, ignore file and a CI step, with the bulk reformat kept in its own commit and added to .git-blame-ignore-revs.
  • Repair malformed HTML in posts — pointing prettier at the content turned out to be a decent HTML linter: 16 of 76 posts would not parse, and every failure was genuinely broken markup.
  • Migrate the server to TypeScript — no compile step, because Node 24 strips types at runtime and tsc only checks.
  • Migrate the browser code to TypeScript — and with it the hand-written type declaration that could silently drift from the code it described.
  • Drop the client-side post rendering — an abandoned experiment that intercepted every post link and re-rendered it in the browser.

Bugs the tests found

  • Repair the RSS feed — four bugs in the one part of the routing no test reached, including 100 images that resolved against the subscriber's own domain rather than the blog.
  • Repair five broken internal links — started as one broken link I had noticed; writing a test to catch it found four more.
  • Load d3 so the running chart renders — the chart on an old post had been quietly blank.
  • Make npm run dev work again — broken on master since the TypeScript migration.
  • Correct post meta-data gaps — a category typo that put one post in a category of its own, and another with no category at all.

Safety nets

  • 404 unmatched URLs — they used to redirect to the homepage, which made every broken link on the site look like it worked. Five real ones were hiding behind it.
  • Cover the MCP server with tests — 170 lines with no tests, driven through a real client so the tools are called the way an agent calls them.
  • Cover meta-data parsing properly — it was tested, but only the easy half.
  • Add security response headers — the site sent none at all. The content-security policy starts in report-only, deliberately.

Making it easier to work on

  • Run the CI checks locally — the same checks CI runs, on commit and push instead of after.
  • Run the git hooks in a container — so they work whatever version of node happens to be on the host.
  • Add a compose dev service — with this, developing the blog needs no node on the host at all.
  • Let Dependabot keep dependencies current — weekly, with minor and patch bumps grouped into one PR and majors left separate.
  • Add a scaffolding script for new posts — npm run new:post writes the meta-data block and the usual section skeleton, so starting a post is no longer a copy-paste job.
  • Document the layout and conventions — the parts that are only discoverable by reading the code.

New features

  • Expose the blog over MCP — a read-only endpoint at /mcp, so the posts can be searched and read by an agent. Add it as a connector and ask it things.
